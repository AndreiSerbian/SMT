# Release Readiness Audit — Photo Mask Customization (Timeweb)

Аудит только на чтение и проверку. Маски, перекраска, база данных, Supabase и Beget не меняются. После отчёта — STOP.

## Что будет сделано

1. **Таблица текущего статуса** по 3 коробкам (с бантом / сумка / магнитная): маски, перекраска MAIN/SIDE/BOW/HANDLES, модалка, палитра из БД, серый фон для «Белый»/«Белый бриллиант», мобильная версия, «Добавить в корзину», сохранение конфигурации, +10%, заказ, уведомления — только по фактическому коду.
2. **Карта ассетов**: коробка → фото-источник → main → side → акцент → запись в mockups.json и рендерер. Проверка существования путей, регистра имён, дублей, старых/черновых/отладочных файлов, на которые ещё есть ссылки.
3. **Production build**: запуск текущей команды сборки, ошибки/предупреждения, таблица `SOURCE → DIST → EXISTS` для каждого ассета масок.
4. **Прямые URL**: отдача собранной папки локальным статическим сервером с правилами из `.htaccess`-логики; проверка, что PNG/WEBP/JSON отдаются как файлы с верным MIME, а не как `index.html`.
5. **Совместимость с Timeweb**: поиск зависимостей от Netlify/Vercel/Lovable/localhost, `base` в Vite, абсолютные/относительные пути, разбор `public/.htaccess` (SPA-fallback, кэш, ModPagespeed).
6. **Кэш и старые маски**: проверка, у каких ассетов есть `?v=`, у каких нет (включая сам mockups.json и файлы, загружаемые без версии), правила кэша в `.htaccess`; предложение минимального решения.
7. **Оптимизатор Timeweb**: риски объединения/минификации JS/CSS, перекодирования в WebP, влияние на чтение пикселей из canvas.
8. **Canvas**: crossOrigin, отсутствие tainted canvas, порядок загрузки (перекраска только после загрузки всех карт), размеры и DPR — через Playwright в Chromium (Safari/Android — только анализ кода, отмечу как непроверенное).
9. **Визуальный регресс**: скриншоты всех 3 коробок — тёмный/светлый MAIN, Белый, Белый бриллиант, контрастная боковушка, тёмный/светлый акцент; поиск ореолов, дыр, выхода цвета, потери объёма.
10. **Мобильная проверка** 360/375/390 px: видимость превью, образцы цветов, прокрутка, горизонтальный вылет, кнопка закрытия.
11. **Палитра**: источник цветов, наличие uuid/name/russian_name/hex_code, где hex остаётся ключом интерфейса.
12. **Коммерция**: сверка реализованного (кнопка в модалке, раздельные строки корзины, +10%/+0%, лестница скидок, cart_items, серверный пересчёт, уведомления) с фактическим кодом; отметка, что развёрнуто ли обновлённое серверное оформление заказа и что сквозной реальный заказ не проверялся.
13. **Supabase/Beget**: оценка переносимости JSON-снимка в cart_items, отсутствие новых зависимостей.
14. **Отладочные артефакты** в public/ и dist/ (диагностические карты, скрипты, QA-изображения).
15. **Вес ассетов** на каждую коробку и что грузится сразу, а что — только при открытии модалки.
16. **Обработка ошибок**: сломанный путь, отсутствующая маска, недоступные цвета — модалка не должна падать (проверка через перехват запросов в Playwright).

## Итоговый отчёт (в чате, формат из документа, разделы 1–14)

CURRENT STATUS, два вердикта (PREVIEW и COMMERCE), риски Timeweb, риск старых масок, результат сборки, визуальная и мобильная проверка, статус коммерции, влияние на Supabase, P0/P1/P2, точный список файлов к изменению, чек-лист выкладки на Timeweb, GO/NO-GO отдельно для превью и для полной коммерции.

## Технические детали

- Сборка пишет только в `dist/` (нужна для проверки ассетов); исходники не меняются.
- Статический сервер для проверки URL — временный, в /tmp.
- Никаких миграций, деплоя функций и тестовых заказов (реальный заказ рассылает уведомления менеджеру).
