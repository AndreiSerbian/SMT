# Реализация: конфигуратор коробок → корзина → цены → заказ → уведомления

Аудит утверждён. Ниже — план реализации по вашему PRD. Маски и recolor не трогаем, миграций БД нет.

## Что делаем по шагам

1. **Палитра.** `mockupService.getPalette()` начинает отдавать `{ key, colorId, hex, nameRu, nameEn }` — `colorId` это uuid из таблицы цветов, `key`/`hex` остаются прежними, поэтому текущий UI конфигуратора не ломается.
2. **Базовая конфигурация.** Для каждой коробки определяем исходные цвета зон из данных товара и `mockups.json`; `changed` считается сравнением с этой базой, а не фактом клика. Если базовый цвет боковушки в данных не задан явно — зона помечается как «база неизвестна» и считается изменённой только при явном выборе пользователем.
3. **Единый расчёт цены** — новый `js/services/pricingService.js`: надбавка +10% один раз, если изменены основной цвет и/или боковушка; лестница скидок 20/30/40/50k → 2/3/4/5%; целые рубли, `round` для надбавки и `floor` для скидки.
4. **Идентичность строки корзины** — `lineKey`: `std:<id>`, `mask:<id>:<main>:<side>:<accent>:<accentColor>`, `design:<id>:<design_id>`. Все операции корзины переходят на `lineKey`. Старые корзины без ключа мягко мигрируют при чтении; позиции печати с `design_id` продолжают работать без потери данных.
5. **Кнопка «Добавить в корзину»** в окне конфигуратора: собирает выбранные цвета, считает `changed` и надбавку, кладёт позицию в корзину с сохранением конфигурации.
6. **Корзина** показывает для настроенной позиции: основной цвет, боковушку, бант или ручки, «Кастомизация: +10%» либо «Доплата за кастомизацию: нет», цену за штуку и сумму строки. Обычные позиции выглядят как раньше.
7. **Оформление заказа**: убираем две копии лестницы скидок, в каждую позицию добавляем снимок цены (база, надбавка, процент скидки, итоговая цена за штуку, количество, сумма строки).
8. **Сервер считает цены сам** (`order-processing`): берёт актуальные цены товаров, проверяет цвета по таблице цветов, заново считает надбавку, суммы, скидку и минимальную сумму заказа. Числа из браузера — только для сравнения.
9. **Расхождение цены**: сервер авторитетен, но не молча — возвращает признак пересчёта и обе суммы; клиенту показываем «Цена была обновлена перед оформлением заказа. Итоговая сумма: …», менеджеру в уведомление добавляется пометка о пересчёте. Если после пересчёта сумма ниже минимальной — заказ не создаётся, клиенту возвращается новая сумма и просьба скорректировать корзину.
10. **Уведомления менеджеру** (Telegram и письмо): для настроенной позиции выводим цвета зон, базовую цену, надбавку, скидку и итог; для обычной позиции лишних строк нет. В таблицу Google Sheets по-прежнему уходит полный состав заказа.
11. **Формулировки клиенту**: «Ваш заказ принят», ссылка-подтверждение сохраняется, добавляется «Менеджер свяжется с вами для подтверждения деталей и итоговой стоимости». Страница подтверждения переформулируется как подтверждение со стороны клиента, а не одобрение менеджером.
12. **Проверки**: прогон сценариев A–R из вашего PRD, включая обычный товар, только бант, только ручки, боковушка, основной цвет, комбинация зон (+10%, не +20%), смешанная корзина, пороги скидок в обе стороны, старая корзина без ключа, старый заказ без новых полей, позиция печати рядом с настроенной.

## Технические детали

- Изменяемые файлы: `js/services/mockupService.js`, `js/services/pricingService.js` (новый), `js/services/cartService.js`, `js/components/mockupPreviewModal.js`, `js/components/orderComponent.js`, `js/main.js`, `supabase/functions/order-processing/index.ts`, `supabase/functions/order-confirmation/index.ts`, `roadmap.md`.
- Форма позиции корзины: обычная — `{ id, quantity, lineKey }`; настроенная — плюс `customization` (`schemaVersion: 1`, `mockupType`, `main`/`side`/`accent` с `colorId`, `hex`, `nameRu`, `nameEn`, `changed`, `paidBoxCustomization`, `surchargePct`); при оформлении добавляется `pricing`.
- Растровые данные не сохраняются нигде.
- Хранение — существующая колонка `cart_items` в заказах, тип JSONB. Миграций нет, старые заказы читаются как раньше.
- Округление синхронизировано между фронтом и сервером: надбавка `round`, скидка `floor`, всё в целых рублях.
- Файлы масок, recolor-конвейера и `js/customizer/*` не изменяются; по печати проводится отдельная проверка на регрессию.
