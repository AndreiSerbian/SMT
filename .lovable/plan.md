# Release-проверка protocol v2 перед TimeWeb

Работаем строго по вашему файлу, шаг за шагом; любой провал = STOP и отчёт.
Старый сайт продолжает получать отказ `CHECKOUT_UPDATE_REQUIRED` — совместимость не включаем.

## Шаги
1. **Тесты.** Перепрогнать 6 серверных (Deno) + 5 фронтенд (Node) тестов на текущем коде. Не 11/11 → STOP, ничего не публикуем.
2. **Проверка базы только на чтение.** Сверить `create_checkout_order`, `claim_checkout_notifications`, `checkout_requests` со схемой `orders` (отдельных `order_items`/`customers` нет — клиенты в `b2b_clients`, позиции в `orders.cart_items`) и с реальными аргументами вызовов в `index.ts`: типы, обязательные поля, связи, значения по умолчанию, права EXECUTE, RLS, search_path, повтор того же request_id, откат при ошибке, аренда уведомлений. Запустить линтер базы. Нашлась несовместимость → STOP до публикации.
3. **Публикация** только `order-processing`, если 1–2 прошли полностью. Записать хэш исходника и данные о публикации, насколько их отдаёт инфраструктура.
4. **Проверка в production без заказов:** A — quote валидной корзины; B — неверное количество; C — поддельный/устаревший quote при create; D — старый протокол → `CHECKOUT_UPDATE_REQUIRED`. Потом проверить, что не появилось новых заказов, клиентов, записей `checkout_requests`; уведомления не отправляются (до записи заказа ни одна проверка не доходит).
5. **Сборка сайта** локально (`npm run build`), без загрузки. Проверить, что в собранных файлах есть protocol 2 и snapshot `ef4d14cd` (56 товаров). Определить: нужен полный `dist/` или отдельные файлы (ожидаемо полный `dist/`, так как изменён код с хэшами в именах).
6. **RELEASE PASSPORT** по вашему шаблону + ровно один статус `TIMEWEB RELEASE: GO` или `NO-GO`; при GO — точная инструкция загрузки. Затем STOP.

## Не делаем
Новые миграции, изменения цен, удаление `product_prices`, создание заказов, публикация других функций, загрузка на TimeWeb, любые доработки сверх этого.

- Хэш текущего `index.ts`: `9a8677c9…`; ранее опубликован `79d6cc3a…` — шаг 3 устраняет расхождение.
- Если в шаге 2 найдётся ошибка в RPC, её исправление потребует новой миграции — это будет отдельный запрос к вам, не в этом проходе.
