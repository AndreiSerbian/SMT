# Phase 1 — Анализ фото и статические raster masks (magnet_box / photo_closed_45)

Только подготовка ассетов и визуальная проверка. Production-код не меняется, интеграция — только после утверждения масок.

## Источник

- PRIMARY REFERENCE: `2-1.png`, 750×750, белая коробка с белым бантом на светлом фоне.
- Фото с красной боковушкой — только behavioral reference (какая площадь считается SIDE), пиксели из него не берутся.
- Геометрия, перспектива, форма банта и пропорции не меняются. Все маски pixel-to-pixel соответствуют source 750×750.

## Что видно на фото (границы зон)

- Верхняя плоскость — четырёхугольник, задаётся четырьмя вершинами коробки.
- Правая длинная грань — передняя поверхность с горизонтальным стыком крышка/корпус и закрывающей панелью.
- Левая грань — торцевая панель; вокруг неё узкие светлые конструктивные кромки (верхняя, передняя, нижняя, задняя).
- Бант — узел, две петли, два хвоста; частично выходит за силуэт коробки, между петлями и хвостами видна поверхность коробки.

Разделение:
- MAIN = top + передняя поверхность + закрывающая панель + все кромки/рамка вокруг торцевой панели.
- SIDE = только внутреннее поле торцевой панели, кромки исключены (внутренний отступ по контуру).
- BOW = полный силуэт ленты, просветы между петлями/хвостами вырезаны.

## Как строятся маски

1. Яркостная/контрастная сегментация используется ТОЛЬКО как черновой кандидат-контур. Она не является итоговой границей ни для одной зоны: источник — белая коробка + белый бант + светлый фон.
2. MAIN и SIDE режутся полигонами по фактическим вершинам, снятым с пиксельной сетки фото, затем пересекаются с выверенным силуэтом.
3. SIDE строится непосредственно по фактическому контуру внутренней торцевой панели на PRIMARY REFERENCE, без автоматического равномерного inset от внешнего контура боковой грани. Верхняя и передняя границы — по реально видимым стыкам; нижняя и левая/задняя включаются только в той форме, в какой действительно читаются на фото. Не создаются конструктивные кромки, которые на исходнике нельзя уверенно определить. Все пиксели видимой оболочки вокруг SIDE остаются в MAIN.
4. BOW: черновой контур по локальному контрасту и градиенту, далее ручная полигональная доводка узла, петель, хвостов и вырезание просветов между ними.
5. Все границы вручную проверяются и корректируются по PRIMARY REFERENCE на высоком зуме. Недопустимо: потерянные белые блики, срезанные края банта, протечка фона внутрь масок.
6. Три цветовые маски приводятся к практически нулевому взаимному перекрытию; края сглаживаются на 1–1.5 px без ореолов и щелей.

## Модель слоёв

Концептуально: MAIN SHELL / SIDEWALLS — нижний слой, BOW — накладка поверх них. Область под бантом геометрически существует и принадлежит корпусу. Для статичной фото-маски допустимо, что `mask_main` исключает видимые пиксели банта.

## Ассеты (создаются на этом этапе)

```text
public/mockups/magnet_box/default/photo_closed_45/
├── source.webp
├── masks/  mask_main.png  mask_side.png  mask_bow.png
└── maps/   luminance.webp  shadows.webp  highlights.webp  details.webp
```

Маски — 8-битные grayscale PNG 750×750 (255 = зона, 0 = вне зоны, промежуточные значения только на краю). Файлы в `maps/` создаются как черновые: их качество разложения НЕ является блокером приёмки Phase 1, стратегия рендера финализируется в Phase 2.

## Приоритетные deliverables Phase 1

`mask_main.png`, `mask_side.png`, `mask_bow.png`, debug-скриншоты, метрики перекрытия, отчёт о ручных коррекциях.

## Debug QA

Изолированная debug-страница (не подключается к каталогу): source + три полупрозрачных overlay (MAIN красный, SIDE зелёный, BOW синий) с чекбоксами включения/выключения.

Скриншоты: обзорный 750×750 для каждой маски плюс увеличенные кропы:
A — верхняя/передняя/нижняя структурные кромки SIDE; B — узел банта; C — левая петля; D — правая петля; E — хвосты на фоне коробки; F — края банта на фоне; G — переход MAIN/SIDE.

## Критерии приёмки Phase 1

MAIN точно покрывает свою зону; SIDE — только внутреннее поле боковой панели; структурная рамка остаётся в MAIN; BOW содержит всю видимую ленту; просветы между петлями и хвостами остаются дырами; фоновые пиксели не попадают в маски; значимые пиксели объекта не теряются; выравнивание строго 750×750 pixel-to-pixel; антиалиасинг без ореолов; перекрытие цветовых масок ≈ 0 кроме края.

После выдачи deliverables — STOP. Canvas recoloring и интеграция не начинаются.

## Границы задачи

Никакого AI/сегментации в runtime, никаких SVG-масок, backend-рендеринга, изменений Supabase, цен, логики товаров и customizer. Никаких ограничений на сочетания цветов: mainColor, sideColor, bowColor полностью независимы.
