## 5. Корень проблемы
Цену сохраняют в одном месте (`products`), а витрина берёт её из копии (snapshot), которая обновляется только вручную. Кроме того, при оформлении заказ создаётся сразу по серверной цене, а клиента лишь уведомляют об изменении после факта (`alert` в orderComponent после `clearCart`). Именно так получается сценарий «видел X → заказ создан по Y» без согласия покупателя.

## 6. Вариант A — накладывать актуальные цены поверх snapshot
- Один лёгкий запрос `id, price_rub` (около 56 строк, меньше 3 КБ), параллельно со snapshot. Публичное чтение активных товаров уже разрешено правилами доступа.
- Скорость: +1 запрос; цены подставляются до показа или сразу после.
- Если запрос не удался: показываем цену из snapshot, но помечаем её как неподтверждённую. Окончательную гарантию даёт шаг C.
- Минус: витрина сильнее привязывается к Supabase. Это смягчается, если запрос оформить как своё API, например Edge Function `catalog-prices`: при переезде в РФ меняется только адрес.

## 7. Вариант B — автоматически обновлять snapshot
- Нужен серверный обработчик (после сохранения или по триггеру), который собирает JSON и заливает его на TimeWeb по FTP/SFTP. Для этого нужны данные доступа к TimeWeb на сервере, нужен атомарный выпуск (сначала snapshot, потом version) и откат.
- Сборка сайта не нужна, но появляется новая точка отказа и хранение секретов хостинга. Слишком тяжело для текущего этапа; разумнее делать вместе с переездом.

## 8. Вариант C — подтверждение цены сервером перед оформлением
- В `order-processing` добавляется режим `quote` (только расчёт, без записи заказа и без уведомлений), который использует тот же `recalculateOrder`, поэтому логика не дублируется.
- При нажатии «Оформить» клиент сначала получает quote. Если итог отличается — показываем новую сумму с разбивкой и кнопкой «Подтвердить новую сумму». Заказ создаётся только после подтверждения.
- Дополнительная защита: клиент передаёт `confirmedTotal`; если сервер насчитал другую сумму, он возвращает 409 с новым quote, а не создаёт заказ.
- Не зависит от Supabase-специфики (обычный POST), переносится при переезде без изменений.

## 9. Рекомендуемая архитектура
**C + упрощённый ручной выпуск snapshot сейчас, A — следующим этапом (через собственное API), B — после переезда.**

Если актуальную цену получить нельзя: витрина показывает цену из snapshot, но оформить заказ без успешного quote нельзя — появляется сообщение «Не удалось проверить цену, попробуйте позже». Ни один заказ не создаётся по сумме, которую покупатель не видел и не подтвердил.

## 11. Риски
- Quote добавляет около 0,5–1 с к оформлению.
- Пока обновление цены в A и выпуск snapshot не автоматизированы, витрина может показывать старую цену. Деньги это не затрагивает: в заказ она не попадёт без подтверждения.
- Старые вкладки с прежним кодом будут получать 409, если начнут присылать `confirmedTotal`. Поэтому проверка мягкая: без `confirmedTotal` сервер работает как сейчас.
