# Phase 1 — Анализ фото и статические raster masks (magnet_box / photo_closed_45)

Только подготовка ассетов и визуальная проверка. Production-код не меняется, интеграция — только после утверждения масок.

## Источник

- PRIMARY REFERENCE: `2-1.png`, 750×750, белая коробка с белым бантом на светлом фоне.
- Фото с красной боковушкой — только behavioral reference (какая площадь считается SIDE), пиксели из него не берутся.
- Геометрия, перспектива, форма банта и пропорции не меняются. Все маски pixel-to-pixel соответствуют source 750×750.

## Что видно на фото (границы зон)

- Верхняя плоскость — четырёхугольник, задаётся четырьмя вершинами коробки.
- Правая длинная грань — передняя поверхность с горизонтальным стыком крышка/корпус и закрывающей панелью.
- Левая грань — торцевая панель; вокруг неё узкие светлые конструктивные кромки (верхняя, передняя, нижняя, задняя).
- Бант — узел, две петли, два хвоста; частично выходит за силуэт коробки, между петлями и хвостами видна поверхность коробки.

Разделение:
- MAIN = top + передняя поверхность + закрывающая панель + все кромки/рамка вокруг торцевой панели.
- SIDE = только внутреннее поле торцевой панели, кромки исключены (внутренний отступ по контуру).
- BOW = полный силуэт ленты, просветы между петлями/хвостами вырезаны.

## Как строятся маски

1. Силуэт коробки отделяется от фона по яркости с последующей чисткой (заливка, морфология) — даёт общий контур.
2. MAIN и SIDE режутся полигонами по фактическим вершинам, снятым с пиксельной сетки фото (проверка координат по увеличенным фрагментам), затем пересекаются с силуэтом.
3. SIDE = полигон торцевой панели, ужатый внутрь на толщину кромки, измеренную по фото; отнятая полоса уходит в MAIN.
4. BOW: стартовая сегментация по локальному контрасту и градиенту (бант белый на белом — порог по яркости один не годится), далее ручная полигональная доводка узла, петель, хвостов и вырезание просветов; контур проверяется на увеличении.
5. Все три маски приводятся к взаимной непересекаемости, края сглаживаются на 1–1.5 px (без ореолов и щелей).

## Ассеты (создаются на этом этапе)

```text
public/mockups/magnet_box/default/photo_closed_45/
├── source.webp
├── masks/  mask_main.png  mask_side.png  mask_bow.png
└── maps/   luminance.webp  shadows.webp  highlights.webp  details.webp
```

Маски — 8-битные grayscale PNG 750×750 (255 = зона, 0 = вне зоны, промежуточные значения только на краю). Карты в `maps/` извлекаются из фото и сохраняют светотень, складки сатина и стыки для Phase 2.

## Debug preview

Отдельная изолированная страница-проверка (не подключается к каталогу): source + три полупрозрачных overlay — MAIN красный, SIDE зелёный, BOW синий, с чекбоксами включения/выключения каждого слоя. Скриншоты этой страницы прикладываются к отчёту.

## Отчёт Phase 1

Возвращается: описание поверхностей, границы MAIN/SIDE/BOW, debug-скриншоты, метрики перекрытия (MAIN∩SIDE, MAIN∩BOW, SIDE∩BOW в пикселях) и список мест, требующих ручной доводки (ожидаемо: край банта на белом фоне, узел, тонкая кромка вокруг торцевой панели, контакт хвостов с тенью).

После этого STOP — Canvas recoloring и интеграция в mockup preview выполняются только после утверждения геометрии масок.

## Границы задачи

Никакого AI/сегментации в runtime, никаких SVG-масок, backend-рендеринга, изменений Supabase, цен, логики товаров и customizer. Никаких ограничений на сочетания цветов: mainColor, sideColor, bowColor полностью независимы.
