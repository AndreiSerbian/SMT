# Phase 1 — Анализ фото и статические raster masks (magnet_box / photo_closed_45)

Только подготовка ассетов и визуальная проверка. Production-код не меняется, Canvas recoloring и Phase 2 не начинаются.

## Источник

- PRIMARY REFERENCE: `2-1.png`, 750×750, белая коробка с белым бантом на светлом фоне.
- Фото с красной боковушкой — только behavioral reference (какая площадь считается SIDE); пиксели из него не берутся.
- Геометрия, перспектива, форма банта и пропорции не меняются. Все маски pixel-to-pixel соответствуют source 750×750.

## Определение зон

- **MAIN** = вся видимая оболочка коробки, кроме внутреннего поля SIDE и видимого BOW: top, передняя поверхность, передняя закрывающая панель и все реально видимые участки корпуса. Формулировка «вся рамка вокруг SIDE» не используется, если такая рамка не читается на фото целиком.
- **SIDE** = только фактически видимое внутреннее поле торцевой панели на левой грани. SIDE ≠ вся левая грань. SIDE ≠ внешняя грань минус фиксированный inset. Между SIDE и соседними поверхностями местами могут быть видны светлые конструктивные участки/канты — их наличие, форма и толщина определяются исключительно по PRIMARY REFERENCE; кромки, которые нельзя уверенно различить на исходнике, не создаются.
- **BOW** = полный видимый силуэт ленты: узел, левая петля, правая петля, левый и правый хвосты. Просветы между петлями, хвостами и между лентой и коробкой остаются вне маски.

## Модель слоёв

MAIN + SIDE — нижний слой, BOW — верхний визуальный слой. Поверхность коробки под бантом физически существует, но для статичной raster-маски допустимо, что видимые пиксели банта исключены из `mask_main.png`.

## Как строятся маски

1. Яркостная/контрастная сегментация — только черновой кандидат-контур, не итоговая граница ни для одной зоны (белое на белом на светлом фоне).
2. Все финальные границы вручную проверяются и корректируются по source на высоком зуме. Недопустимо: потерянные белые блики, срезанные края банта, протечка фона внутрь масок.
3. **SIDE**: маска строится непосредственно по фактическому контуру внутреннего поля торцевой панели. Каждая граница определяется отдельно — по реально видимым стыкам, изменению плоскости, контрасту, конструктивным переходам и pixel grid. Никакого uniform inset и никакого предположения о четырёх одинаковых кромках. При визуально неоднозначном участке: увеличить фрагмент source, выбрать наиболее обоснованную границу по реальным пикселям, поправить маску вручную, не дорисовывать предполагаемую конструкцию.
4. **MAIN**: всё остальное видимое тело коробки вне внутреннего поля SIDE и вне видимого BOW.
5. **BOW**: rough contour по локальному контрасту/градиенту, затем ручная коррекция непосредственно по фактическим краям source. Метод свободный — Canvas path, raster brush, erase, ручное попиксельное редактирование, polygon там, где он подходит. Важна pixel accuracy, а не техника. Поверхность коробки между элементами ленты в BOW не входит.
6. **Antialiasing**: без global blur, без feather всей маски, без фиксированного размытия 1–1.5 px. Жёсткие геометрические края коробки остаются резкими; промежуточный alpha — только на тех граничных пикселях, где антиалиасинг уже присутствует в source. Для сатинового банта мягкий alpha-переход допускается там, где он соответствует реальному фотографическому краю. Маска повторяет source, а не сглаживает его.
7. Три цветовые маски приводятся к практически нулевому взаимному перекрытию: допустимы только минимальные shared alpha-пиксели на antialiased-границе; без видимых gaps, halos и color seams.

## Ассеты

```text
public/mockups/magnet_box/default/photo_closed_45/
├── source.webp
└── masks/
    ├── mask_main.png
    ├── mask_side.png
    └── mask_bow.png
```

Маски — 8-битные grayscale PNG 750×750 (255 = зона, 0 = вне зоны, промежуточные значения только на краю по правилу выше). Черновые `maps/` (luminance, shadows, highlights, details) могут быть сгенерированы, но их качество не является блокером приёмки Phase 1 — стратегия рендера финализируется в Phase 2.

## Debug QA

Изолированная debug-страница (не подключается к каталогу): source + полупрозрачные overlay MAIN (красный), SIDE (зелёный), BOW (синий) с чекбоксами включения/выключения.

Скриншоты:
- full MAIN overlay, full SIDE overlay, full BOW overlay, combined overlay (750×750);
- A — увеличенный crop всей видимой торцевой панели с одновременным overlay MAIN и SIDE: где заканчивается SIDE, где начинается MAIN, нет искусственного inset, нет потерянных пикселей, нет захода SIDE на оболочку;
- B — узел банта; C — левая петля; D — правая петля; E — хвосты на фоне коробки; F — края банта на фоне.
Проверяются: края ленты, внутренние отверстия, самопересечения ленты, белый бант на белом корпусе, отсутствие захваченных пикселей коробки.

Дополнительно отчёт: MAIN ∩ SIDE px, MAIN ∩ BOW px, SIDE ∩ BOW px и перечень участков, скорректированных вручную.

## Критерии приёмки

1. SIDE соответствует фактическому внутреннему полю торцевой панели.
2. Предполагаемые «нижние/задние кромки» не дорисованы без подтверждения source.
3. Uniform inset не используется.
4. MAIN содержит всё остальное видимое тело коробки.
5. BOW точно повторяет реальный силуэт ленты.
6. Просветы внутри банта остаются прозрачными.
7. Жёсткие края коробки не размыты.
8. Мягкость края банта соответствует source.
9. Маски pixel-aligned 750×750.
10. Нет видимых gaps / halos / color bleeding.
11. Production-код не изменён.

После выдачи масок и debug QA — STOP.

## Границы задачи

Никакого AI/сегментации в runtime, никаких SVG-масок, backend-рендеринга, изменений Supabase, цен, логики товаров и customizer. Ограничений на сочетания цветов нет: mainColor, sideColor, bowColor независимы.
